# 128 Technology (Juniper Session Smart Networking)

> 128 Technology builds the Session Smart Networking platform: a software-defined, session-aware
> IP routing and network services stack built on Secure Vector Routing (SVR), a tunnel-free
> routing protocol. The Session Smart Router (SSR) carries the data and control plane; the
> Session Smart Conductor is the centralized management, policy and provisioning engine. Juniper
> Networks acquired the company in 2020, but the developer surface still lives under the
> 128 Technology identity — docs.128technology.com, github.com/128technology, and the
> @128technology npm scope.

Generated by API Evangelist from the company's public documentation and repositories on
2026-09-05. Not published by 128 Technology.

## How the API works

The SSR exposes a YANG-modeled configuration and state tree over three interfaces: a REST API
rooted at `/api/v1`, an equivalent GraphQL API, and NETCONF. All three are served by the
customer's OWN deployed router or conductor. There is no vendor-hosted API endpoint, no
developer signup, and no API key issuance — the base URL is the address of your instance.

- Authenticate: `POST https://<SSR address>/api/v1/login` with `{"username": "...", "password": "..."}`
- The response returns `{"token": "<RS256 JWT>"}`
- Every subsequent call carries `Authorization: Bearer <token>`
- Authorization is RBAC: the role's capabilities (`config-read`, `config-write`, `provisioning`)
  and its resource groups determine which routers, tenants and services the token can reach.

The interactive references are served from the instance itself and are NOT publicly reachable:
`https://<SSR address>/documentation/swagger` and `https://<SSR address>/documentation/graphql`.
No OpenAPI, GraphQL SDL or Postman collection is published at any public URL. To discover which
API a given operation uses, the vendor's own advice is to run the PCLI `trace` command.

## Known gaps

- No OpenAPI, GraphQL SDL, AsyncAPI, Postman collection or JSON Schema is published at any
  public URL. The Swagger and GraphQL references exist but only on a deployed instance.
- No `/.well-known/` document on any host; `128technology.com` presents an invalid TLS
  certificate and answers 200 with Juniper marketing HTML for every path, including a control
  path that cannot exist.
- No idempotency mechanism, no published error reference, no published API rate limits, no
  status page, no A2A agent card, and no MCP server.
- No first-party client SDK for the REST or GraphQL surface in any language.
